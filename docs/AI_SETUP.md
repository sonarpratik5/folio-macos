# Native reading assistant

From home, use the sparkle button on Continue reading, or open a paper's details and choose **Ask Folio**. The sheet restores the saved conversation and Paper at a glance. Opening it never starts a provider request. Send, Explain selection and Generate/Regenerate are explicit actions; Cancel and Done stop active work. A page citation opens the source in the reader. Asking from home preserves the current reader until you choose a source or Resume.

## Providers

The default is **Codex CLI, GPT-6.1 Terra, medium reasoning**, matching the web app. Install Codex CLI and run `codex login` yourself in Terminal. Folio searches the standard Homebrew/local/Codex app locations and PATH; set `FOLIO_CODEX_CLI` in the app's launch environment for another executable path. The packaged `FolioPaperTools` helper must remain beside FolioMac. No shell or arbitrary-file tools are exposed to the model.

**Claude API** is an explicit choice in the assistant's provider button. Supply `ANTHROPIC_API_KEY` in the native project’s `.env` or Folio's launch environment; optionally set `FOLIO_ASSISTANT_MODEL` (default `claude-sonnet-5-5`). Existing keys previously imported into this Mac’s login Keychain remain supported. AI panel header menus contain provider and Claude model choices. Settings has no AI section or credential controls. Local app builds record only the project `.env` path in their bundle metadata, so copies in Applications can still read that file. Folio then checks the working directory and the project containing `.build/Folio.app`; launch environment takes priority. It never copies secrets into the bundle or searches the sibling web app’s `.env`; the existing explicit `--import-claude-key-from <path/to/.env>` command remains available. Readiness checks can read the local `.env`; Keychain presence checks remain attributes-only and non-interactive. Credential operations prohibit authentication UI; blocked access fails inline. Successful access is cached until exit. To inherit variables set in a terminal, launch the executable directly from that terminal: `.build/Folio.app/Contents/MacOS/FolioMac`. Finder launches may have a different environment. No provider switches automatically when setup, sign-in, model access or quota fails.

## Context and local storage

Requests share extracted paper text with the selected provider. Chat starts from a compact map of at most 12K characters, adds up to two locally ranked question excerpts, reuses recent complete exchanges within 32K UTF-8 bytes, and can retrieve relevant pages/search the paper or web when needed. Explicit “here/this page” questions also receive a small reading-page excerpt when no selection is attached. Long historical turns are shortened only in outgoing context; saved chats retain their full text. The local extracted lookup corpus is capped at 1.6 MB; individual results, total tool calls and request duration are bounded. Truncated excerpts are explicitly marked. Web queries should remain minimal and relevant.

Paper at a glance uses up to 800 distributed passages / 40K UTF-8 bytes (including source-label allowance) and validates every cited source against that extraction. An unsupported card is omitted rather than fabricated. Results persist atomically at `Assistant/<paper UUID>.json` inside the selected library. They are separate from PDF bytes and library metadata. Corrupt/incompatible history or changed paper text disables reuse and leaves the file untouched.

Current boundaries: answers display after completion with basic Markdown and source/page buttons. Rendered LaTeX, streaming, multiple conversation threads, OpenReview analysis and concept-graph refinement are not implemented. Scanned PDFs require OCR, which is absent. Fake-provider and generated-PDF checks do not establish live account/model access; see [testing](TESTING.md).

## OpenReview credentials

The Peer Reviews section uses `OPENREVIEW_TOKEN`, `OPENREVIEW_USERNAME` and `OPENREVIEW_PASSWORD` from the same local `.env`, with launch-environment values taking priority per variable. A token is used first. Without one, the client signs in at `https://api2.openreview.net/login` using the username/password. A rejected token (401/403) triggers one sign-in and retry when both login values are configured. Refreshed tokens are reused in memory by the client, never written back to `.env` or the library. With no credentials, public lookup remains available. Authentication occurs only during explicit review search/load actions; opening the section does not sign in. Errors omit credentials and raw API responses.

The local build’s `FolioEnvironmentFile` metadata points to the original native project `.env`, including after copying to Applications. The project must stay at that path. If moved, rebuild the app or supply launch-environment variables. The bundle contains no `.env` file or credential values.
