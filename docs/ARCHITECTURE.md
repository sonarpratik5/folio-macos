## Annotation palette

`AnnotationPalette` owns Preview-matched highlight constants shared by reader swatches and Workspace highlight writes. PDFKit performs highlight blending; the app stores opaque sRGB with no extra compositing. Existing web fills (including old .43-on-white fills) remain recognized for note color filtering. Underline and text inks keep their earlier values. Apple palette values were read from the installed AnnotationKit helper and theme resource during development; the shipped app uses constants and public AppKit/PDFKit only.

## Data flow and invariants

App → shared Workspace → repository load → library. NSOpenPanel → temporary security-scope access → validated PDF → UUID managed copy → atomic manifest → Workspace.open → PDFCanvas. Each import is independent; there is no source-identity deduplication. UUID filenames avoid path traversal from untrusted PDF titles. Titles are display text.

Views call Workspace. PDFKit page notifications defer main-actor publication and check active document identity. PDFCanvas suppresses page-change notifications while assigning/restoring documents. Records/UI are one-based; PDFKit uses zero-based indices. No global PDFView singleton.

Selection → per-line/per-page finite crop-clipped PDFKit bounds → shared group ID → Workspace page changes → PDFEditHistory → managed PDF atomic save → history/revision refresh. A group is one logical selection, including cross-page marks and at most one written comment. Before committing new highlights, PDFEditing.replacingHighlights subtracts their page-space rectangles from existing highlight regions (per quad when present), retaining uncovered fragments and group metadata. Fully covered written highlight comments become Text notes; partially covered comments stay on one fragment. Workspace routes both markSelection and selection-anchored note creation through this plan, committing removal and additions together. Underlines and other annotation types are excluded. Written quote/group/style/image metadata uses private PDF keys alongside standard editable annotations and appearance streams. PDFImageAnnotation draws a bitmap stamp; base64 PNG data reconstructs its appearance for later movement/resizing. FreeText uses Helvetica and stored size/ink to restore PDFKit's editable style getters after reopening; exported appearance remains standard PDF.

PDFEditHistory takes independent before/after annotation snapshots, validates document/page ownership, rejects duplicate/stale changes and records only successful saves. Replacing PDFAnnotation.copy() with independently constructed supported annotations avoids shared PDF dictionaries dropping edited annotations on subsequent saves. Undo/redo restore fresh annotation objects, preserve supported hit ordering, and retain the same history stack when saving fails. Expected live page arrays detect out-of-band mutation; generated Popup companions are snapshotted with their parent and recreated during encoding. Unrelated link/widget/foreign objects are retained rather than reconstructed; relative layering against such foreign objects is a remaining verification limit. Workspace.prepareAnnotationEdit restores only ToolPDFView’s tracked transient FreeText visibility before copying replacements, snapshotting changes, Undo or Redo. The sharp vector renderer temporarily hides PDFKit appearances; capturing those flags previously made restored text invisible and saved that state on reopen. Genuine hidden annotations are not globally revealed. Histories reset on document open. Text-field Undo stays with AppKit; reader Undo uses the annotation history.

Workspace loads a data-backed document independent of later managed-file replacements. AnnotationDraft captures the page, point, quote, original annotation and selection at editor opening. A small anchored popover saves text or note-image input on Done, outside click or reader transitions; empty new drafts and Cancel create no annotation/history. Note no-op detection compares attachments as well as text. PDFNotes.read and draft loading accept image-only Text notes while excluding bare marks. Attachment changes also persist new-note drafts. Failed popover saves retain the same draft ID and pending input, rebind a detached original uniquely to the restored before-state, and reject stale/ambiguous targets rather than appending duplicates. Empty FreeText deletion keeps the editor until its undoable write succeeds. Quit attempts to finish the current draft and stays open if writing fails. Eraser previews collect hits over interpolated pointer segments, then commit the entire stroke once. Move/resize preview changes geometry without mutating the saved annotation until mouse-up. Stars/position remain separate metadata; source PDF content is not flattened or rebuilt.

## View persistence and export boundaries

ReaderState captures each debounced view save as a store/UUID/ReadingPosition snapshot. Pending snapshots are keyed by paper, retained on write failure and flushed at document replacement and Workspace's finish-editor gate (including navigation and quit). A new document is not ready to save until its initial fit. Custom zoom consumes its stored scale once, then reuses the valid live scale on subsequent fit passes.

Workspace export calls LibraryRepository.allowsExport before serialization/write. It resolves the library root and the destination's nearest existing ancestor, appends any missing components, and rejects the root or its descendants by path components. This covers symlinked parent paths for new files; it does not provide filesystem locking against concurrent path replacement.

## Reader work reuse

LibraryView keys full note/annotation scans to paper IDs, document session and PDF revision, rather than title/star/page metadata. Scans still run synchronously when the library mounts or that identity changes.

Workspace lazily caches written notes for the active PDF. Document replacement, revision changes (including writing-page insertion/removal) and annotation-save rollback invalidate the cache. Rollback invalidates even when the revision is unchanged because history restores fresh annotation objects. Page navigation and unrelated UI state reuse the cached result.

ReaderSidebarParts evaluates thumbnails inside lazy PageRow bodies. Its shared NSCache uses a 256-entry limit and 16 MiB estimated decoded-pixel cost budget; NSCache eviction limits are advisory. Keys include a fresh Workspace document-session UUID, page number, rotation and revision, so reopening a managed copy cannot reuse a previous document's preview. Outline traversal stops at 600 rows even when a node has many siblings. PDFKit access remains on the main actor.

ReaderState caches normalized page text (including original UTF-16 highlight offsets) across queries in a separate NSCache with 256-page/16 MiB estimated storage budgets. Closing Find retains that cache. Workspace document replacement clears query, selections and cache; revisions, rollback and page-structure changes cancel old searches, clear cached text/selections and debounce a fresh search when a query remains. Search yields after every page and each 64 selections, with cancellation checks before creating further selections. Find navigation finishes any active editor before indexing results again, because saving can invalidate them. PDFPage.string and PDFSelection remain on the main actor.

NormalizedSearchText handles printable ASCII followed by ASCII directly, avoiding per-character NSString composed-range lookup and Unicode folding. At non-ASCII boundaries it preserves the composed-character/folding path so combining marks, emoji and Unicode offsets retain their existing behavior. Whitespace, soft hyphens and line-break hyphenation keep their dedicated rules.

## User-triggered AI flow

Library Ask action → assistant sheet → load that managed PDF without changing Workspace.activeID/document → deterministic extracted context and saved assistant snapshot. Only Send/Explain/Generate invokes AssistantService. Chat sends the stable compact map (12K characters), up to two locally ranked question excerpts (1,400 UTF-16 units each), and a 2K-character opening excerpt of the reading page for explicit “here/this page/section” questions without a selection. Other extracted text stays local until a read/search tool requests it. Shared `PaperLookup.search` ignores common English question words, matches whole tokens and weights rare terms across pages; this is lexical retrieval, not embeddings. Lookup JSON is capped at 1.6 MB with per-page truncation reported; read windows are 12K UTF-16 units, search returns at most eight ranked page excerpts. Overview and review paper evidence supply at most 800 distributed passages / 40K UTF-8 bytes including quoted-text/label allowance, validates exact integer source IDs, and stores original extracted passages rather than model quotations. Recent chat input retains complete exchanges within 32K UTF-8 bytes (also accounting for current context against a 96K-byte target); individual historical turns above 12K bytes retain their start/end with an explicit omission marker. Stored history is unchanged. New user turns preserve their reading page; Ask hides this metadata while retaining selected-passage presentation. History and overview use `Assistant/<paper UUID>.json`, schema/identity/text-fingerprint validation and atomic writes; malformed or changed-document state fails closed.

Codex uses a private temporary directory, ephemeral/read-only execution, ignored user/project rules, disabled shell/files/plugins/skills and a credential-stripped environment. Its MCP helper receives only the chosen extracted-text JSON path, permits read/search only, and caps calls/input. Claude resolves ANTHROPIC_API_KEY from the launch environment, LocalDotEnv, then existing Keychain for explicit API requests and supports the same local paper tools plus hosted web search. Both enforce bounded output/time/tool use and cancellation without fallback. The helper is packaged beside FolioMac; no Node/web server is needed. Provider messages and paper/web evidence remain untrusted. Full AI parity limitations are tracked in PORTING/QUALITY.

## Extension boundaries

FolioCore is the storage/model/service seam; FolioMac owns native UI and main-actor orchestration. Injectable HTTP/process transports permit disposable verification without live accounts. Future UI/provider expansion must retain bounded user-triggered context, cancellation and reader identity. The [porting map](PORTING.md) identifies remaining parity gaps. Swift Package Manager opens directly in Xcode; no generated Xcode project, Node toolchain or third-party package is required.

### Credential access and Insights ownership

FolioApp initializes ClaudeKeyStore.prepareNonInteractiveAccess, which sets SecKeychainSetUserInteractionAllowed(false) once for this process; every credential operation guards its success. Legacy login-Keychain ACL dialogs ignored the query-only policy on this Mac. This setting does not unlock the Keychain or weaken its ACL. All ClaudeKeyStore operations additionally share nonInteractiveQuery: LAContext.interactionNotAllowed plus the legacy login-Keychain kSecUseAuthenticationUIFail policy. Readiness requests attributes; provider requests can retrieve the secret only without authentication UI. Save adds a new UUID account under the same service; its identifier is stored in UserDefaults only on successful add. Legacy default-account reads remain supported. Old inaccessible items may survive best-effort cleanup. `CredentialSession` serializes secret loads and caches successful retrieval in process memory. Credential APIs update the cache only after Keychain success; blocked access returns an inline setup error. Settings contains no AI section; AI panel headers expose provider and Claude model choices; the existing explicit dotenv-import command and previously imported credentials are retained. `InsightsView` owns an assistant model per inspected paper, cancels generation on departure, restores saved overviews, and routes citations through `Workspace.open(paper, at:)`. InsightsPaper uses one outer scroll view with an adaptive context/contents layout, reading the managed PDF locally for its embedded outline and written comments. GlancePanel owns the web-matched three-anchor presentation: width-driven columns/stack, selected idea and source-disclosure state, lightly irregular pastel outlines and an expanded sheet sharing the same model. Its Read page opens the inspected paper; Ask about this routes the first validated source through Workspace.present with no automatic send. Generation and persistence stay in PaperAssistantModel; the abstract is shown in full separately. Saved conversations come from the inspected model’s fingerprint-validated AssistantThreads; Workspace.resumeChat opens the correct paper and selects its thread in the reader-owned model without sending. Workspace's separate `insightsPaperID` preserves reader identity/position during inspection. `Workspace.navigate` commits pending edits before changing library destinations.

### Selected-text explanations

[SelectionInsightView](../Sources/FolioMac/SelectionInsightView.swift) owns a transient request/model and SelectionInsightPopup. PDFCanvas.Coordinator hosts the popup in a transient NSPopover anchored using PDFKit’s page-to-view conversion of the first selected line; it clears the host and request on native dismissal. PDFCanvas.ToolPDFView.finishSelection and Shift-arrow keyUp route into Workspace.explainFinishedSelection. Only insightsMode + Select + reading can create a bounded, page-tagged request; identical text/page is deduplicated. A bounded 24-entry process-local cache keys completed answers by content fingerprint, provider/model, selection and page; errors/cancellations are not cached and retry bypasses it. Each uncached result view has its own SwiftUI task and AssistantService; identity changes/removal cancel the process/network request. The popup extracts its paper through `PaperAssistantModel.readPaper` without loading the shared chat model or either assistant repository; unreadable or stale history cannot block a selection explanation. Chat and overview loading still fail closed on invalid history. No chat repository reads or writes occur. The selected provider is shared with the other AI features.

`AssistantPaper.selectionContext` locates normalized selections up to 12K characters in the selected extracted page. Short selections receive at most 1,600 context characters; selections above 800 characters receive only the preceding/following 600 characters each, avoiding duplication of the selection. Unlocatable/cross-page selections receive no unrelated fallback. AssistantService adds this quoted, page-tagged evidence beside the selection and reuses the stable map. Research instructions prioritize supplied context, then targeted missing paper evidence, with web access when useful or requested. Full-paper questions require coverage-aware section reads rather than an automatic full-text prompt. Existing request-scoped corpus, byte caps and provider tool permissions are unchanged.

Selection insight sizing: `InsightScrollBody` measures the natural response-stack height at the fixed 380pt popup width, then limits its viewport to 260pt. `NSHostingController.sizingOptions = [.preferredContentSize]` propagates loading/result/error height changes to NSPopover. The popup has no fixed overall height; header and quote stay outside the response scroller. Thin material replaces the opaque fill; accessibility Reduce Transparency/Increase Contrast use the existing solid panel color.

LocalDotEnv reads each requested variable from the running user's `~/Library/Application Support/FolioMac/.env`, then the working-directory `.env`, then the project above `.build/Folio.app`. No build-recorded absolute path is consulted; secrets are not bundled or exported. NativeReviewsClient merges launch and dotenv credentials per variable; injected test environments disable file discovery. Its private authentication actor keeps tokens in memory, signs in on demand at api2.openreview.net/login, and retries one rejected request after login. Redirects must remain on the original API host. Codex child environments strip all configured Claude/OpenReview credential variables.

## Folder navigation and recent visits

`Workspace.openFolder` explicitly scans a selected directory’s regular PDFs recursively (case-insensitive extension; hidden entries, packages and symlink descendants skipped), imports managed copies and selects that folder. `LibrarySnapshot.folders` preserves empty folders; `PaperRecord.folderPath` and `sourcePath` preserve membership and avoid reimporting the same path on refresh. Repository metadata saves retain the folder list. Optional fields preserve schema-1 decoding. `Workspace.libraryPapers` scopes folder (always including descendant membership) and Recent destinations; `recentPapers` sorts actual reader visits, and LibrarySidebar offers the first five excluding the built-in guide as direct resume buttons. `visitedAt` is set on a successful reader open; older records infer visits only when lastOpened is later than addedAt (or addedAt was absent). `open` resolves the current stored record before restoring position, including calls with a stale row snapshot. Insights browsing still does not write reader state.

Reader rotation tracks intrinsic angles by PDFPage identity, retaining removed writing pages for Undo/Redo. Structural writes use the same original-rotation save boundary as annotation/export writes; successful page changes reapply view rotation/fit and refresh active search. Writing insertion discards the annotation redo branch only after successful persistence. Inspector note updates return save success so failed writes retain the editing UI.

## Local bundle replacement

`build-app.sh` copies executables/resources into a unique staging directory (including its iconset), remaps compiler source/debug paths, strips executable debug-map symbols, rejects bundled home paths/private data files/recognized credential patterns, ad-hoc signs, and deep/strict verifies before moving the previous bundle aside and publishing the new directory. Fresh executable inodes avoid stale macOS code-signature state after in-place rebuilds; failed packaging leaves the previous bundle intact. Installed copies require the same stage/verify/replace procedure.

## Local Skim highlights

[SkimClassifier](../Sources/FolioCore/SkimClassifier.swift) owns uncased WordPiece tokenization, 512-position windows with three replayed sentences, SEP-position five-class Core ML logits and probability/density selection. The fixed adapted model and vocabulary are [documented here](../Models/Skim/MODEL.md); model identity/label order are checked before loading. The runtime has no Python/server/provider dependency. The [build-only exporter](../scripts/export-skim.py) traces an existing adapted checkpoint, converts FP16, compares synthetic native predictions with PyTorch, and records provenance/token fixtures in the manifest. Packaging copies the compiled model into Resources/Skim and fails clearly if it is absent; SwiftPM development binaries resolve the repository's Models/Skim directory.

[Workspace+Skim](../Sources/FolioMac/Workspace+Skim.swift) extracts PDFKit page strings on the UI actor while yielding between pages, invokes the actor-isolated native classifier off the UI actor, then maps original UTF-16 ranges to per-line crop-clipped PDFKit geometry. Single PDF soft-wrap newlines become spaces before sentence segmentation without changing UTF-16 offsets; blank paragraph breaks remain. Display groups up to three sentences per text block, split at blank boundaries/pages; one eligible prediction per block at probability ≥0.5, without section-based bans or forced facet balance. The non-interactive AnnotationOverlay draws the enabled facets using PDFView coordinate conversion, keeping zoom/crop/rotation in the native view pipeline. MarginMarksView reads only active-document, enabled SkimMarks and uses MarginLayout to merge nearby passage guides, with explicit Goal/Method/Result labels and role-colored bars along the rotated page edge. It never enumerates saved annotations; clicking a guide navigates to its first passage without selecting or editing an annotation. No PDF annotations, note records, history entries or network requests are created. A request identity plus task cancellation prevent stale results after toggling off, document switches, library exits or page insertion/Undo/Redo. Inference failure is explicit; there is no model fallback.

## Structural save and recovery boundary — 2026-11-15

Workspace.savePageStructure constructs the next mutable PaperRecord pageCount/currentPage/star set and publishes papers only after LibraryRepository.saveStructure succeeds. Repository load and save share schema/record validation. saveStructure validates both the candidate and previous files, atomically writes a local structure-rollback.json containing the previous PDF bytes and manifest, replaces PDF then manifest, and removes the journal as the commit boundary. Failure restores both previous files; failed restoration keeps the journal. Repository initialization and subsequent load/save boundaries recover an outstanding journal before proceeding. Recovery is idempotent; malformed data blocks access without replacing it. This is process-interruption recovery with atomic file replacements, not a power-loss/fsync guarantee or multi-process protocol.

The structural caller rolls back the in-memory insertion/removal on failure and advances history only on success. AI stores are cancelled/replaced after successful structure changes and document opens; ReaderView identities use the store object so replacement models load again even for the same paper ID. Old fingerprinted history files remain preserved; text-change history migration remains a separate limitation.

Active removal uses finishEditorIfNeeded before repository deletion and clears pending writing, editor, passage/structural history, requests and AI store after successful removal. PaperAssistantModel.persist returns success so delete cannot erase its own failure. ReadingPositionStore stages a candidate cache, writes atomically, then publishes it; invalid initial files block subsequent writes until an external repair is readable. ReaderState reports save errors instead of swallowing them.
