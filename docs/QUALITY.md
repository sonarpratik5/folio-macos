# Quality and limits

- Q1: PDFKit serialization is not a full-fidelity guarantee for arbitrary PDFs, signatures, forms, embedded fonts or existing third-party annotations. Tests cover only generated fixtures and preserve the source. Unchanged foreign annotation objects are retained; relative layering against edited objects and rich third-party FreeText/callout metadata need broader verification. Imported supported markup can be edited/erased intentionally; links/widgets/foreign stamps are excluded from hit targets. Add a synthetic fidelity matrix before broad export claims.
- Q2: Highlight overlap clipping uses axis-aligned page-space rectangles, including bounds of imported quads; skewed third-party quad appearance needs fidelity verification. The latest-highlight change has fixture/persistence evidence but no fresh pointer-gesture GUI check. Multi-column/rotated/cropped/non-Latin and cross-page selection geometry needs interaction testing. Scanned PDFs need OCR, which is absent. Core tools now select/recolor/edit/erase supported annotations; Undo remains session-only. Fixture geometry covers crop/rotation in page space; the full rotated/cropped interaction matrix is still needed. Text longer than its available page region remains in Contents but may be clipped visually.
- Q3: Writing-page structural edits use a rollback journal coordinating PDF and manifest; process-interrupted saves restore the prior pair. This is not an fsync/power-loss guarantee. Import remains separate copy/manifest writes: rollback handles manifest failure, but a crash can leave an orphan. New-note/text drafts have local autosave/recovery; edits to existing annotations and inspector drafts are not durable crash-recovery drafts. Failed inspector/popover Save and empty-text deletion retain the in-memory draft for retry and block navigation. Uniquely identifiable restored annotations are rebound after rollback; indistinguishable stale imported targets fail closed and require reselecting. No version history, migration beyond schema rejection or multi-process coordination. Do not run concurrent app instances against the same library.
- Q4: PDF loading, explicit Find, thumbnail generation, annotation encoding and all-library note scanning run on the main actor. Library scans now invalidate on paper identity/document session/PDF revision instead of title/star/page metadata; scans remain synchronous on mount and PDF changes. Active-document written notes now reuse a scan between document/revision/rollback changes; reader thumbnails render within lazy rows with NSCache eviction budgets (256 entries / 16 MiB estimated pixels, advisory rather than a hard memory ceiling). History retains annotation snapshots including pasted PNG bytes for the session. Large libraries/papers may still pause the UI; no bounded async repository yet. Metadata is saved on page changes without coalescing. Find caches normalized page text with separate 256-page/16 MiB estimated-cost NSCache budgets and yields between pages/64-selection batches; a single page extraction/normalization and matching pass can still block. Synthetic debug normalization timing improved; no fresh Instruments, GUI responsiveness, end-to-end latency or large-PDF memory benchmark.
- Q5: Minimum window size is 960×640; toolbar scrolls if space is tight. VoiceOver, full keyboard focus, split-pane restoration and all display-scale combinations need a broader audit. Dark mode optionally dims the PDF display without changing exported colors. Default theme uses native regular glass on macOS 26+ and standard material on 14/15, with solid Reduce Transparency/Increase Contrast fallbacks. Palette contrast tests cover nine key pairs, not every compositor background, disabled state or display. Older-OS material appearance still requires runtime verification.
- Q6: Local app is ad-hoc signed, unsandboxed and unnotarized. No App Store entitlements, security-scoped bookmark persistence, automatic updates, universal binary or Finder file associations configured. Packaging is for development on the build machine.
- Q7: No web-data migration. Export browser annotations to PDFs first where supported; browser-local stars/chats/drafts will not appear automatically. Reimports create separate copies. Native removal deletes only the managed copy and library entry after confirmation.
- Q8: Native chat, selection Insights, overview, reviews, concept map, arXiv import, note images and ruled writing pages are implemented. These parity paths now include offline typeset LaTeX, global conversation search, below-canvas writing and study-copy continuation sheets. [PORTING](PORTING.md) is authoritative for the audited feature matrix.
- Q9: AI tests primarily use fake providers, generated PDFs and disposable processes. Live Codex chat and overview passed against a synthetic three-page paper on 2026-11-15; live Claude, web retrieval, long-paper answer quality and exhaustive section coverage remain unverified. Codex CLI flags/model availability and Claude model/web-tool access depend on installed versions/accounts; unavailable choices fail without fallback. Launch-environment setup has no credential entry form. PDF text extraction occurs on the main actor and may pause large documents; OCR/equation fidelity and full-paper coverage are not guaranteed. Codex answers display after completion; Claude supports streaming. Text fingerprints intentionally block reusing old AI files after paper text changes; there is no migration/recovery UI for that case yet.

Verification belongs in [TESTING](TESTING.md). Open quality items are context, not automatic authorization to work on them.

Fresh GUI evidence covers a synthetic paper in light appearance; populated-chat continuation is covered by a persistence/orchestration test, not a fresh live-provider chat. - Local dotenv discovery first uses the build-recorded native project `.env` path, allowing Applications copies to work. If the project moves, rebuild or supply launch-environment credentials. - Folder browsing: recursive explicit scan with direct/descendant filtering; no directory watcher, external-change reconciliation or security-scoped bookmark persistence. - Functionality audit: fresh interactive launch was blocked by automatic approval review usage exhaustion. Unit/render tests are not evidence that every control works end to end; live integrations, Finder/dialog flows and broader PDF/accessibility matrices remain open. See [audited matrix](PORTING.md).

- Startup repair (2026-11-14): latest three human-reported quits were pre-main macOS code-signature kills, despite subsequent valid on-disk signatures. Fresh bundle replacement and staged packaging address the suspected stale-inode/signature-cache trigger. Four installed-app disposable launches passed; this is bounded verification, not proof that every runtime path is crash-free. Older RegisterApplication aborts were also present in historical reports; no new abort was observed in the repaired Launch Services checks.

Question retrieval uses whole-token lexical matching and English stop words; synonyms, inflections and unsegmented scripts can need explicit page tools. Only the best window per page is auto-selected, at most two pages. The 40K-byte structured evidence budget samples long papers; it does not establish absence of claims from omitted sections. Byte budgets are conservative context limits, not measured provider token counts or billing savings.

Annotation audit (2026-11-15): synthetic light-mode GUI checks cover highlight/underline gestures, on-page text, eraser, image-only note creation/listing and Undo/Redo. A reader-view regression and fresh GUI retest verify visible text after erase/Undo/reopen. Broader imported-PDF, rotated/cropped gesture, dark/accessibility and third-party export matrices remain unverified. Note images remain library sidecars; exporting a PDF does not package those separate files.

- Skim quality: the adapted checkpoint comes from a tiny full-text pilot, not a human-validated whole-paper corpus. No precision/accuracy improvement is promised. PDF text order, references, equations, headings and multi-column extraction can mislead sentence roles. Scans without text have no Skim marks; no OCR is added. Display density is block-based and scores are uncalibrated. The model has an 80-WordPiece sentence limit and 512-position windows. FP16 parity fixtures cover nine synthetic sentences, not a representative accuracy benchmark. First model load is local and may take time; cancellation is checked between inference windows. Compiled weights are local ignored build assets; fresh clones need the existing adapted checkpoint and documented export step.

- Reader parity limits (2026-11-15): recursive imports and PDF export still perform PDFKit/file work on the main actor; large folders or image-heavy exports can pause. Conversation file scanning/filtering run off the main actor, but history remains an in-memory text index. Writing's pending 650 ms buffer is not a durable crash-recovery draft. Generated fixture and disposable GUI evidence do not certify arbitrary PDFs, RTL/non-Latin continuation fonts, every TeX command or third-party viewer behavior. Embedded note images use Folio metadata plus ordinary visible PDF image sheets, rather than standard PDF file-attachment objects. Dimming darkens the entire PDF canvas, including figures; the Settings switch restores original display brightness.
